## [Unreleased]

### Added
- **Apple app, first slice** (ADR-0010, branch `apple`): `apple/` holds one SwiftUI multiplatform app for iPhone, iPad and a native Mac (minimum iOS/iPadOS/macOS 26.0, bundle ID `com.ambysto.steady`, personal-team builds use `.dev`). The Overview screen shows what `NWPathMonitor` reports: connected or not, Wi‑Fi/wired/mobile data, router address, IPv4/IPv6, DNS, metered network, Low Data Mode and why a connection is unavailable. Logic lives in the `SteadyKit` Swift package (`swift test --package-path apple/SteadyKit`). See `apple/README.md`.
- `scripts/locales_to_xcstrings.py` generates the Apple String Catalogs and the Swift parameter table from `app/locales/*.json` (positional placeholders, plural forms by Apple's rules); `tests/test_apple_catalog.py` fails when they are stale. 21 new `ui.path.*` keys in all 9 languages.
- **Apple app: live measurements** while the Overview screen is open, with the Windows monitor's targets and intervals: ICMP to the router, 1.1.1.1 and 8.8.8.8 every second, TCP to port 443 every 10 seconds, grouped per minute like `app/monitor.py`; shows the latest round-trip time, loss and jitter per target and check #5 "Ping quality" over the last hour. The local network permission text and `CFBundleDisplayName` are generated from the catalogs (`apple/Config/Generated.xcconfig`, `InfoPlist.xcstrings`). 8 new `ui.live.*`/`ui.permission.*` keys.
- Shared diagnosis test vectors `spec/diagnosis/` (ADR-0010), starting with check #5 ping quality (20 cases, including the threshold boundaries); `tests/test_diagnosis_vectors.py` runs them against the Python rules and `SteadyKitTests` against the Swift port.
- **Installer / uninstaller** (SIC-32): `scripts/build.py` packages the app with PyInstaller into a folder that runs without Python + a zip file (`--smoke` test-runs the built version: the monitor serves the UI, all 9 languages present). Double-clicking `Stable Internet Connection.exe` for the first time installs it per user (no Admin needed): copies it to `%LOCALAPPDATA%\Programs\Stable Internet Connection`, registers the monitor task, a Start menu shortcut, the tray icon at sign-in, and an Apps & features entry. Uninstall: stops the app + monitor, restores every tweak and the failover metrics (new Admin operation `restore-all`, via UAC), removes the task/shortcuts/registry entry/folder; data is deleted only when the user chooses to, and never while there is still a backup that could not be restored. Uninstall is blocked when it is not run from the exact installed folder (to avoid deleting some other folder by mistake). `app/runtime.py` makes the task, UAC and shortcuts work correctly both from source and from the packaged build.
- **Backup connection (failover)** (`app/failover.py`, ADR-0008, SIC-38), off by default: detects the paths to the Internet (Wi‑Fi, wired Ethernet, USB 4G, a phone's Wi‑Fi hotspot) and measures each path every 5s with a TCP connection bound to that path's IP; when the primary path has had no Internet for ≥ 20s while another path has been up for ≥ 10s, it lowers the InterfaceMetric of the backup path (first saving the original metric in `backup.json`, reading it back to verify, rolling back on error); once the primary path has been stable for 120s, it switches back. 60s spacing, at most 6 times/hour, and it turns itself off after switching back and forth 3 times within 30 minutes. Without Admin rights it only notifies (event + toast) and switches when the user clicks (UAC). Dry-run mode. UI: a "Backup connection" section in Settings, a card on Overview when there are ≥ 2 paths. API `/api/failover`, `/api/failover/prefer/{ifIndex}`, `/api/failover/restore`; the Admin process adds `path-prefer`, `path-restore`.
- Analysis for a phone/tablet version: `docs/MOBILE.md`.
- **App window and tray icon** (`app/desktop.py`, SIC-29, ADR-0002): a frameless pywebview window with 3 traffic-light buttons on the left (close = hide to tray, minimize, maximize; double-click the title bar to maximize; drag the title bar/top of the screen to move; drag a corner to resize), a tray icon that changes color with the status (green/red/gray) with a translated tooltip and menu (Open, Reconnect Wi‑Fi, Quit). Opening it a second time only brings the existing window to the front. Automatically reconnects when the monitor restarts. `requirements.txt` (pywebview 6.2.1, pystray 0.19.5, Pillow) — only the desktop shell needs it; `scripts/desktop/run_desktop.pyw`; `python -m app.desktop --selftest [--screenshot]`.
- **Real UI** (`web/`, SIC-28) following the approved mockup, running at `http://127.0.0.1:47613/`: Overview (status, latency chart for 15 minutes/24 hours/7 days with packet loss, incident regions and change markers; metrics; suggestions; recent incidents; quick actions; watchdog), Optimize (manual steps, enabling/disabling tweaks via job + UAC, before/after results), Diagnostics (run, expand each check, bufferbloat with confirmation), Log (filters, grouped by day), Settings (language, light/dark, start with Windows, notifications, watchdog). Plain JS, no libraries, keeps a strict CSP; responsive down to phone size. New API: `/api/state` includes `settings`, `/api/autostart`, `/api/history?bucket=`. Monitor start/stop events are translatable.
- Measuring the impact of changes (`app/impact.py`, ADR-0007): compares monitor metrics before/after enabling a tweak or completing a manual step — two equal windows (at most 24h), counting only monitored time, with a minimum threshold so as not to draw conclusions from noise. `GET /api/impact`; `/api/tweaks` includes the result for enabled tweaks. Tweak events now carry `tweak_id`.
- Suggestions and manual steps (`app/suggestions.py`): 9 steps (rotate the antennas, move the PC/router, turn off the modem's Wi‑Fi, change channel, turn off MLO, update the driver, plug in a cable, enable SQM, change DNS) appear when diagnostics have evidence, together with related tweaks, ordered by severity. `GET /api/suggestions`, `POST /api/manual/{id}/done`; completed steps show before/after results. The mockup has a Suggestions card on Overview and a Manual steps group on Optimize.
- DNS change detection (`app/dnswatch.py`, read-only): reads DNS via `GetAdaptersAddresses`; when DNS changes on the same network, it records `dns_changed` and shows a toast; remembered across restarts. `settings.json` → `dns_watch`.
- 7 new languages (machine-translated, need review by native speakers): 简体中文 (`zh-Hans`), Español, Français, Deutsch, 日本語, 한국어, Português (Brasil) — all keys complete. Windows in other Chinese/Portuguese variants automatically picks the closest one (`zh-TW` → `zh-Hans`, `pt-PT` → `pt-BR`).
- UI mockup (SIC-27, awaiting approval) `docs/mockup/` and the design token set `web/tokens.css` (light/dark); `scripts/build_mockup.py` generates `locales.js` and the single-file version `docs/mockup/dist/`. 88 `ui.*` keys for the screens.
- Multi-language support (ADR-0006, `app/i18n.py`, `app/locales/en.json`, `vi.json`): choose the language via `settings.json` → `ui.language` (default `en`, `auto` = follow Windows) or `POST /api/settings {"ui": {"language": "vi"}}`, effective immediately. `GET /api/i18n` returns the list of languages and the translations for the UI. Missing translations fall back to English; formatting only accepts `{name}`/`{name:format}`; supports plurals and decimal commas. Tests check the catalogs (extra keys, mismatched placeholders, keys used in code must exist in `en.json`) and an English-only naming test (`tests/test_naming.py`).
- Project folder skeleton and the initial set of design documents (README, ARCHITECTURE, TWEAKS, DIAGNOSTICS, WATCHDOG, SECURITY, BASELINE, ROADMAP, OPEN-QUESTIONS, ADR-0001).
- Measurements of the PC's current state on 2026-10-03 in `docs/BASELINE.md`.
- ADR-0002: macOS-style UI in a pywebview window, Mac-style control buttons.
- `scripts/manual/apply-lowrisk.ps1` (with a read-only `-ShowState`) and `scripts/manual/restore.ps1`: manually apply/restore the low-risk tweaks, with a JSON backup.
- `scripts/monitor/ping-logger.ps1`: background logger (per-minute ping, Wi‑Fi, incidents) and `scripts/monitor/report.ps1`: before/after report.
- `docs/EXPERIMENT-LOG.md`: experiment log, EXP-001 applied at 2026-10-03 10:59.
- `scripts/monitor/install-autostart.ps1` + `start-logger-hidden.vbs`: the logger starts hidden at sign-in (Startup folder, no Admin needed).
- `app/config.py` (paths, `settings.json`, `backup.json` written atomically; a corrupt backup raises an error instead of being silently treated as absent) and `app/winutil.py` (PowerShell `-EncodedCommand` returning JSON, OEM netsh, Admin check, Wi‑Fi status, network adapters, uplink/gateway — read-only). Tests in `tests/test_winutil.py` (`python -m unittest discover -s tests -t .`).
- `app/icmp.py` (ping via `IcmpSendEcho`, ctypes, no Admin needed, no process spawned) and `app/dnsprobe.py` (hand-built UDP DNS packets, skips `fe80::`, benchmarks each DNS server). Network errors return structured results instead of raising exceptions. Tests in `tests/test_probes.py` (fake DNS server on loopback).
- `app/storage.py`: SQLite (`minute_stats`, `wifi_stats`, `events`) shared across threads, purges expired data, imports the PowerShell logger's CSV (re-running does not duplicate rows). The schema is broader than the draft, see `docs/ARCHITECTURE.md`. Tests in `tests/test_storage.py`.
- `app/monitor.py`: pings the router + Internet every second (in parallel, one ICMP handle per thread), reads Wi‑Fi every 5s, detects `router_down` / `internet_down` (≥ 3 consecutive failures, recorded when the incident ends), `wifi_state` / `roam` / `gateway_change` events, aggregates per minute into SQLite, keeps 15 minutes of raw samples in RAM, purges expired data. DB write errors or ping errors do not stop the monitor. Run: `python -m app.monitor`. Tests in `tests/test_monitor.py`.
- Diagnostic check #14 bufferbloat (`app/bufferbloat.py`), **runs only on request**: pings the router and 1.1.1.1 while idle and then during download/upload (4 connections to `speed.cloudflare.com`, at most 10s or 100 MB per direction); reports the added median latency (< 30 ms ok, 30–100 warn, > 100 bad) and ping loss ≥ 20% under load. `python -m app.diagnostics --bufferbloat` or `POST /api/diagnostics/bufferbloat`; not saved to the list of runs.
- Toast notifications (`app/notify.py`): when a network incident lasts ≥ 30s and when it ends; when the watchdog intervenes, turns itself off or hits an error. No external libraries (WinRT via PowerShell, strings passed through base64). Rate-limited, no "restored" notification after the machine sleeps. Enable/disable via `settings.json` → `notify.enabled` (re-read every 10s).
- Catalog of 11 tweaks (`tweaks.CATALOG`, matching `docs/TWEAKS.md` exactly): Wi‑Fi adapter (power saving, Wake on Magic/Pattern, roaming, 5GHz 20MHz, force 802.11ac), power (do not allow turning off the adapter, Wireless Maximum Performance, disable ASPM), network stack (TIME_WAIT, disable IPv6). Tests cross-check the catalog against the documentation (ids and risk levels), run enable→disable for each item on the property layout of a real MT7922 adapter, and read the machine's real state (read-only). Diagnostic #10 now has data. `python -m app.tweaks list` shows the status.
- Non-ICMP connectivity probe (`app/probe.py`): TCP:443 to 1.1.1.1 and 8.8.8.8, HTTP 204 to `cp.cloudflare.com`, every 10s, written to `minute_stats` (`tcp_*`, `http_*`). An `internet_down` incident now opens only when both ping and the latest probe round fail; failing pings while the probe succeeds are no longer an incident. Diagnostic #5 distinguishes "ICMP rate-limited" from "real outage" and from ISP-side faults. Configured in `settings.json` → `probes`.
- API/UI server (`app/server.py`, ADR-0005): runs inside the monitor, with normal rights, `127.0.0.1:47613`. Checks `Host` (against DNS rebinding), a random per-startup token embedded in the page (`X-Token`, constant-time comparison), rejects cross-origin writes, returns no CORS, CSP/anti-framing/CORP, 64 KB body limit and 10s timeout; slow work runs as background jobs. Operations that need Admin run in the child process `app/elevated.py` via UAC (`app/elevation.py`), which accepts only a fixed list of commands. Verified in a real browser: a foreign page cannot read the token, cannot call the API and cannot embed the UI.
- Watchdog (`app/watchdog.py`, `app/actions.py`, ADR-0004, `docs/WATCHDOG.md`): runs in the monitor process, **off by default**. Reacts to `wifi_down` and `router_unreachable` (including silent hangs) after 15s; step 1 reconnects (no Admin needed; disconnects and then reconnects on a silent hang), step 2 restarts the adapter (Admin). Does not intervene when the fault is at the ISP, when a wired network is in use, when the user disconnected Wi‑Fi themselves, within 60s after the machine wakes, or within 120s after a tweak change. Limits: 120s spacing, at most 6 times/hour (counted across restarts too, from the log), turns itself off after 3 consecutive ineffective attempts. `dry_run` mode only records "what it would do". Enabling/disabling in `settings.json` takes effect without a restart.
- Tweak framework (`app/tweaks.py`, `app/winsys.py`, ADR-0003): 4 primitive types (adapter advanced property, HKLM registry DWORD, powercfg AC/DC, adapter binding). Enable: writes `backup.json` **before** applying, reads back to verify, rolls back automatically on error or when it has no effect. Disable: restores and compares against the backup; without a backup it only uses a known default (powercfg refuses). `adopt_backup()` accepts an external backup (e.g. EXP-001) for an already enabled tweak. `python -m app.tweaks list|enable|disable` only prints the plan by default; `--apply` is required to write. The concrete tweak catalog is not declared yet (SIC-18/19/20). Every string passed to PowerShell goes through base64.
- `app/diagnostics.py`: 13 read-only checks per `docs/DIAGNOSTICS.md` (driver, signal, channel interference, drop history, ping quality, DNS, TCP port exhaustion, VPN, wired network, tweaks not enabled, Wi‑Fi 7/MLO, Wi‑Fi modem bridge, physical link). Each check separates a pure evaluation function from the data collection; a check with no data returns `info`, never `ok`. Run with `python -m app.diagnostics [--only 2,13] [--json] [--compare] [--no-save]`; results are saved in the `diagnostic_runs` table. Added to `winutil`: network scan, driver store, DNS servers, Windows events (a single PowerShell command). The thresholds of #11 and #13 are calibrated on the 2026-10-03 data, see `docs/DIAGNOSTICS.md`. Tests in `tests/test_diagnostics.py`.
- `app/autostart.py` + `scripts/monitor/run_monitor.pyw`: starts the monitor automatically at sign-in via Task Scheduler, runs hidden through `pythonw.exe`, logs to `data/monitor.log`. `python -m app.autostart status|install|uninstall`; `install`/`uninstall` only print the commands that would run, and `--apply` must be added to change the machine. Default privilege `LIMITED`, `--highest` when Admin is needed.
- `app/singleton.py`: prevents two monitor instances from running at the same time using a named mutex (no "stale PID" problem as with a PID file). The mutex name is tied to the data folder: only two monitors writing the same `metrics.db` block each other. `python -m app.monitor` exits immediately if another instance is already running; adds `--log-file` (rotating) for running without a console.

### Changed (2026-10-04)

Renamed accordingly: exe `Ambysto Steady.exe`, install folder `%LOCALAPPDATA%\Programs\Ambysto Steady`, shortcuts, the Apps & features entry (key `AmbystoSteady`, Publisher "Ambysto"), task `Ambysto Steady Monitor` (when registering, it removes the old task `StableInternet Monitor` and waits for the old monitor to exit, to avoid contention over the mutex), zip `AmbystoSteady-<version>-win64.zip`, User-Agent `AmbystoSteady/<version>`, 9 languages and documentation. ### Fixed
- Failover could not change the real metric: `interface_metric_set` was mistakenly placed in the `System` Protocol instead of `WindowsSystem`, so every real switch/restore (monitor, UI button, Admin process, uninstall) failed with `AttributeError` even though tests with the fake system still passed. Added a test requiring `WindowsSystem` to have every operation of `System`.
- Failover: a failed switch/restore (e.g. the backup adapter was unplugged) no longer retries and logs an error every 5 seconds (measured 58 error events in 5 minutes, using up the entire toast quota). It now reports once and retries after 60 s → 5 minutes → 15 minutes; the UI still has the "Switch back" button for an unplugged path.
- Failover: clicking "Switch now" while failover was off was automatically rolled back after 5 seconds; it is now the user's choice (`source: manual`) and is kept. The old IP after DHCP changes the IP is no longer counted as a "failed path"; time the machine spends asleep is no longer counted as down/healthy time.
- `backup.json`: two processes (monitor, Admin process) writing at the same time could lose each other's original values. Each write now holds an inter-process lock and changes only its own entry (`config.backup_lock`, `config.put_backup_entry`).
- Uninstall: restores all optimizations **first** and stops if that fails (e.g. UAC declined) — previously it still removed the task, shortcuts and program, leaving changes on the machine with no tool left to undo them. The program folder is deleted only after the uninstaller process has fully exited (previously it only waited ~3 s while the result dialog was still open).
- Install: installing over a running app (an upgrade, or a monitor running from source) now stops the old instance first — previously the exe was locked and the old monitor held port 47613. Rejects a `--target` that is a folder already containing other files (uninstall would delete the whole folder). Reinstalling keeps the task's "highest" privilege if the user had enabled it. `--yes` no longer shows the result dialog (writes to `installer.log`, now UTF-8).
- Watchdog: when Wi‑Fi was lost but the PC was still online via a USB-tethered phone (media "Unspecified") or USB 4G, the dry run still recorded "would reconnect Wi‑Fi". Previously only 802.3 wired adapters counted as another path, and an adapter plugged in after the list was read (once every 5 minutes) was treated as Wi‑Fi. Now every physical non-Wi‑Fi adapter that is Up counts as another path; for an unknown adapter the list is re-read immediately, once per adapter.
- Failover (found while testing for real with an iPhone): the "Switch now" button was rendered from stale state, so the user "switched" to the path already in use and its metric was lowered further (Wi‑Fi = 1). Now the server and the Admin process re-read the routes at click time and reject this before asking for UAC (`failover.result.in_use`). The Backup connection block on Overview and Settings refreshes every ~4 s and re-renders only when the state changes. Previously Settings never refreshed on its own. A switch or restore triggered by the user (including via UAC) is now recorded in the log (`failover_switched` / `failover_restored` / `failover_error`).
- The desktop window had only two sizes (default and maximized), no Snap Layouts and no screen splitting when dragged to an edge, because it was a frameless window with a custom-drawn macOS-style title bar. It now uses the **native Windows frame**: drag any edge, Snap Layouts, Win+arrow keys. The title bar is painted the same color as the page background and follows the light/dark theme. The UI adapts to the window (below 760 px it switches to a tab bar). When maximized, the content column (at most 1200 px) is centered instead of stuck to the left. The selftest (`--selftest`) maximizes, restores, shrinks to 600 × 760 and passes only when the page reflows.
- Desktop window: no longer stuck on the browser's error page when opened before the server is ready (after install/upgrade). Web UI: the "Retry" button no longer duplicates timers; quickly switching Day → Week no longer shows mislabeled data.
- Server: rejecting a write request without first draining the body (body too large, missing token, wrong origin or wrong host) made Windows abort the connection ~1 in 10 times, so the client saw "connection aborted" instead of an error code. It now drains the body (up to 1 MB and 3 seconds) before returning the error.
- Monitor: when the machine slept/froze during an incident, the first successful ping after waking closed the incident with a duration equal to the whole sleep (reproduced: a bogus 28,804 s incident after 8 hours of sleep). Now a gap > 30 s between two ticks (or 10× the ping interval) cuts the open incident off at the last tick, resets the counters and records a `monitor_gap` event.
- Autostart: the task created with `schtasks /SC ONLOGON` kept Task Scheduler's defaults of stopping after 72 hours and not running on battery, which does not suit a 24/7 monitor. The task is now created from XML (`ExecutionTimeLimit` = PT0S, runs on battery too, restarts up to 3 times if it crashes); added `python -m app.autostart validate` so Task Scheduler validates the definition without registering anything.
- Diagnostics: could mistakenly pick "Microsoft Wi‑Fi Direct Virtual Adapter" (also Native 802.11 media) as the Wi‑Fi adapter on machines that do not hide this adapter; physical adapters and connected adapters are now preferred.
- `ping-logger.ps1`: misclassified `internet_down` when the router also lost connectivity during the same incident.
- `ping-logger.ps1`: no longer refuses to start when `logger.pid` contains a PID that has been reused by another process (reproduced with the PID of `explorer.exe`); it is considered "running" only when that process's command line contains `ping-logger.ps1`.

### Changed
- Overview: when only pings to the Internet are lost (the ISP rate-limits ICMP) while the TCP/HTTP probes still get through, the "Packet loss" tile is shown in a neutral color with the note "only ping is limited · real connections are fine" and the packet-loss marks on the chart turn gray; packet loss to the router > 1% is shown separately as a red note. Same rule as check #5. The calculation is split out into `web/js/metrics.js`, tested with `node --test`.
- `metrics.db` schema bumped to v3: the `events` table gets `message_key`, `message_params` (upgraded automatically, keeping old data). Events from the monitor (router/Internet loss, gaps), the watchdog, tweaks, user actions and settings changes are stored as messages; `/api/events`, `/api/history`, `/api/tweaks` and job results are displayed according to `ui.language`/`?lang=`. The `message` column is always in English. Tweak names/groups/notes, enable/disable results, watchdog reasons and Admin process messages also go through the catalog. `python -m app.tweaks ... --lang vi`.
- Test that blocks hard-coded Vietnamese text in `app/` (`tests/test_naming.py`: all displayed text must go through `app/locales`).
- Diagnostics: results are stored as messages and displayed in the selected language (English by default), including saved runs; `python -m app.diagnostics --lang vi`. The API (`/api/*`) translates every message in its responses according to `ui.language` or `?lang=`. Bufferbloat: corrected the sentence "Could not generate upload load" to "Could not generate load in the upload direction".
- Toasts now default to **English** (previously hard-coded Vietnamese); set `ui.language = "vi"` to get Vietnamese. The outage-ended toast states which outage it was ("The outage (Internet is down) lasted 2 minutes 5 seconds."). Whole-hour durations now display "1 hour" instead of "1 hour 0 minutes".
- `metrics.db` schema bumped to v2 (adds the `diagnostic_runs` table); opening a v1 DB upgrades it automatically and keeps the data intact.
- `winutil.get_gateway()` reads the route via `GetBestRoute` (ctypes) instead of PowerShell; PowerShell is now only a fallback.
- ADR-0001 moved to Accepted, amended by ADR-0002 (allows small libraries).
